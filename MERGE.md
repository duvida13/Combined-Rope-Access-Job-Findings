# Manual incremental merge procedure

Use this procedure whenever the user asks for combined findings again. **Do not repeat the initial historical extraction.** The initial snapshot covered the four sources through 29 September 2026.

1. Read [`state/source-checkpoints.json`](state/source-checkpoints.json). The four commit SHAs are the last successfully merged source revisions. Read the existing [`state/observations.csv`](state/observations.csv) and [`vacancies.csv`](vacancies.csv) as the cumulative baseline.
2. Fetch the current default branch of each source repository. For each, compare its saved SHA to current HEAD with `git diff --name-status OLD_SHA..NEW_SHA`. Inspect **only added or modified published job files**: `daily/` and `data/job-index.md` for ChatGPT; `digests/` for Claude; `finds/` for the two Grok repositories. Ignore candidate notes, private context, and Claude's `state/seen_jobs.json` (it includes rejected hits). If a source SHA is unchanged, skip that source entirely.
3. Extract only position title, country when present, vacancy URL, source agent/file, source status, and source date. For a changed cumulative ChatGPT index, compare rows to existing ChatGPT observations and process only new or materially changed rows. For a changed dated file, compare each observation with its prior row signature; do not replay unchanged rows. Do not copy résumé information, contact details, full notes, or application history.
4. Normalize URLs consistently: lower-case the host, remove a leading `www`, use HTTPS, drop a trailing slash and common tracking parameters. Treat an exact normalized URL as one vacancy with **all** reporting agents and claims. Keep different URLs separate unless a human has verified that they are the same posting. Keep general careers pages marked as uncertain and distinguish closed/expired claims from open claims.
5. Append the new source observations to `state/observations.csv`; update `vacancies.csv` without deleting historical links. Create `updates/YYYY-MM-DD.md` with **only the new or changed findings since the saved commits**, separating newly seen URLs from previously listed jobs rechecked by a source. Set `latest.md` to that same delta. Update `conflicts.md` with any substantive disagreements, retaining both claims and links to the source findings. Report the count and the disagreements to the user.
6. Only after the new files are published and checked, replace the four SHAs in `state/source-checkpoints.json` with the source HEADs and set `merged_at` to the run date. If a source is unavailable, leave its SHA unchanged and state clearly that it was not merged. This makes retries safe.

The date in a source file is not proof that a vacancy remains open. No fresh vacancy research is required for this merge. This is an on-request process; do not create a scheduled workflow.
